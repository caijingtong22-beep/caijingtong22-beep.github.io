# 多模态对话意图识别：从数据构建到两阶段微调

电商客服场景里的意图识别，往往同时依赖多轮对话、商品图片和图片中的文字。用户问“内胆是 304 还是 316”，模型需要结合商品参数与上下文，才能判断关注点是商品材质，而不是泛泛的使用体验。

这篇文章整理一套围绕数据质量和监督形式展开的方案：先清洗少量标注数据，再用 OCR、视觉语言模型和文本模型扩展监督，最终形成 Caption 与 VQA 两类训练数据。

## 任务与数据起点

原始笔记记录了约 1,000 条有标签的多模态对话，以及初赛、复赛各约 10,000 条无标签样本。任务包含多轮对话意图识别和图片场景分类。

数据集入口：[ModelScope：电商场景意图识别与图像分类](https://modelscope.cn/datasets/smau0441/www2025-train)。本文讨论的是笔记记录的实验设置，不将数据平台后续版本的规模视为当时的训练规模。

一条样本可以概括为：

```json
{
  "id": "sample_001",
  "instruction": "结合图片与多轮对话，输出用户的意图分类标签。",
  "conversation": "用户：内胆是 316 不锈钢吗？\n客服：请查看商品参数。",
  "image": ["sample_001.jpg"],
  "output": "商品材质"
}
```

只有类别标签时，监督信号比较短。我的数据构建思路是补充图片里可见的商品、参数、页面结构和语义线索，让领域适配阶段获得更丰富的图文关联。

## 第一步：清洗类别混淆

先按类别抽样检查 bad case，再使用 Qwen2.5-VL 与 InternVL 对训练样本预测，筛选模型之间、模型与原标签之间的分歧。

| 情况 | 原始实验中的处理 |
| --- | --- |
| 两模型预测不同，其中一个与原标签一致 | 人工检查并修正标签 |
| 两模型预测不同，且都与原标签不同 | 剔除争议样本 |
| 两模型预测一致，但与原标签不同 | 使用模型共识更新标签 |

笔记记录，第一轮清洗后保留约 900 条。第三条是这次实验采用的启发式策略，模型共识本身并不能保证标签正确；在后续复现中，保留人工复核和独立验证集会更便于判断清洗的实际收益。

## 第二步：构建三类补充数据

### 从官方样本生成详细 Caption

先对图片做 OCR，再将原图、OCR 文本与已有类别提供给视觉语言模型，生成详细描述。描述重点包括商品主体、关键区域、文字内容和与任务有关的属性。

```text
请详细描述这张电商图片。
已知任务类别：商品材质。
OCR 文本：304 不锈钢、316 不锈钢、抗菌内胆、食品接触级。
请结合图片中实际可见的信息，描述商品、材质参数与页面结构。
```

用于前期领域适配的数据保留描述正文，不直接使用模型输出的完整推理过程。这样可以将“看见了什么”的监督与后续任务判断区分开。

```json
{
  "source": "official_train",
  "image": "sample_001.jpg",
  "label": "商品材质",
  "ocr_text": "316 不锈钢 304 不锈钢 抗菌内胆 食品接触级",
  "caption": "图片展示杯类商品详情页，参数区域对比了不同不锈钢内胆的材质与使用特点。用户关注内胆所用金属，与商品材质类别相关。"
}
```

对于原始无标签样本，笔记采用 Qwen2.5-VL、InternVL 和 GLM-4V 三模型投票，仅保留至少两个模型预测一致的样本，再生成相应描述。这里的标签仍然是伪标签。

**评估边界：**参与伪标签构建的无标签样本属于训练流程的一部分，不能再当作完全独立的测试集来解释成绩。复现实验应明确训练、验证与测试划分，避免同源图像或相近对话跨集合泄漏。

### 用文本模型扩展多轮对话

第二类数据主要是纯文本对话。先定义标签集合及类别边界，再让文本模型按类别生成客服场景，初始生成目标为每类约 500 条，最终数量以质检后的保留样本为准。

扩展方式包括：

- 根据类别定义生成多轮客服对话。
- 为短答案补充可核对的材料证据与解释。
- 为已有问答续写一至两轮追问，加入商品属性约束、历史表述或意图转折。

```json
[
  {"role": "user", "content": "这个杯子的内胆是什么材质？"},
  {"role": "assistant", "content": "商品参数标注为 316 不锈钢。"},
  {"role": "user", "content": "那外壳也是同样的材质吗？"},
  {"role": "assistant", "content": "当前参数只说明了内胆材质，外壳需要进一步确认。"}
]
```

这个例子体现的是多轮结构。生成新轮次时，需要保留原问题、已知事实和类别边界，不能为了丰富对话而补出图片或说明中不存在的商品信息。

### 用外部图像扩展视觉分布

第三类数据来自相关开源图像与笔记记录的外部图像源，目标是补充不同商品展示方式、页面样式与场景组合。

处理过程仍然是筛选相关图像、提取 OCR、生成 Caption。和官方有标签样本不同，这些图像通常缺少可靠类别标签，因此先保存可见信息描述，再构造任务问答。

```json
{
  "source": "external_image",
  "image": "external_928.jpg",
  "ocr_text": "内胆：316L 不锈钢；容量：500ml；真空保温",
  "caption": "图片展示保温杯详情页，包含商品主体及内胆材质、容量和保温功能的参数说明。"
}
```

## 第三步：冲突检测与统一格式

生成数据并不等于完成数据构建。原笔记中的冲突检查关注三类情况：

| 检查项 | 需要发现的问题 |
| --- | --- |
| 否定词冲突 | 扩写内容把原答案改判为 incorrect、wrong 等 |
| 短答案未保留 | 原答案很短，扩写却没有保留其关键信息 |
| 选项不一致 | 扩写推荐的选项与原有类别或答案不同 |

这些规则用于筛查候选冲突，不能仅凭字符串出现就判定数据错误。还需要结合原始材料检查语义是否一致。

随后，将不同来源的数据统一整理为 VQA / 分类问答：图片、对话和问题构成输入，类别或答案构成输出。格式转换阶段主要是重组已有信息，可以使用成本较低的中等规模模型；最终再用强模型做质检。

```text
你是一名电商客服数据质量检查员。
请根据图片和问题，检查给定答案是否正确。
正确输出 correct，错误输出 incorrect，不输出额外说明。
问题：{question}
答案：{answer}
```

数据清洗、质量检查与分布调整后，实验整理了约 30,000 条训练数据。原笔记采用了长尾裁剪；实际复现还应检查被裁剪类别的覆盖，避免只提升高频类别。

## Caption 与 VQA 的两阶段训练

同一批原始信息最终形成两种监督形式：

| 阶段 | 数据形式 | 训练目的 |
| --- | --- | --- |
| 领域适配 | 较长的图像 Caption | 学习电商视觉、文字与商品属性之间的关联 |
| 任务对齐 | VQA / 分类问答 | 收敛到明确的意图标签与场景类别 |

结合对应的项目记录，基座为 Qwen2.5-VL-7B-Instruct：第一阶段使用 Caption 数据进行全参数 SFT；第二阶段以 VQA 数据进行 LoRA 微调，rank 设为 16。

项目记录中的复现实验指标如下，不代表官方榜单成绩，也不是本文重新运行得到的结果：

| 任务 | 基线 F1 | 优化后 F1 |
| --- | --- | --- |
| 对话意图识别 | 0.61 | 0.88 |
| 图片场景分类 | 0.64 | 0.84 |

## 复盘

这套流程的关键在于监督形式的变化：短类别标签提供任务方向，详细 Caption 补充领域语义，VQA 再将模型能力收敛到具体任务。多模型投票、冲突检查和质量审核则负责降低生成数据中的噪声。

进一步分析时，值得分别比较清洗、伪标签、纯文本增强、外部图像和两阶段训练的贡献，并在独立验证集上报告每类指标，才能判断收益来自哪里。
